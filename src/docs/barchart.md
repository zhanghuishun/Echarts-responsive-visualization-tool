
# 项目背景
> “随着终端设备形态日益多样化，应用设计需要考虑界面能适配不同的屏幕尺寸、屏幕方向和设备类型。同时要保持多设备体验的连续性” —— HarmonyOS 多设备响应式设计


# 体验原则
由于我们的业务是 Tob（偏“对齐口径 + 可解释 + 稳定可复现”），并且图表常用于分析决策，所以需要在多设备上保持“同一套语义 -> 接近一致的视觉密度”，从而制定如下原则，并在保证体验连续的前提下让大屏获得合理增值：

体验连续——图表的“数据可读性与信息密度”随屏幕变化应尽量平滑，避免因拉伸导致柱子过粗/过细，从而改变读数难度与视觉权重。

体验可控——关键视觉量（例如柱宽、组内间距、可展示类目数）必须有可解释的计算口径，便于设计/前端/产品对齐。

体验增值——当屏幕变大时，不是盲目放大图形，而是通过展示更多类目（或更完整的数据窗口）提升信息量。

## 为什么联想到数据墨水比？
数据墨水比（Data-Ink Ratio）的核心是：图形里“真正用于表达数据的墨水”应占主要比例，避免非数据装饰占用过多空间。

把它转译到响应式柱状图里，可以形成一个可计算的口径：把 X 轴每个类目的“可用带宽（category band）”当作“纸面总墨水空间”，把同一类目内所有柱子的“总宽度（bar ink）”当作“数据墨水”。这样就能定义一个跨屏幕稳定的目标值：

`inkRatio = 数据柱宽总和 / 类目带宽总量`

一旦我们让 `inkRatio` 在屏幕尺寸变化时保持恒定，就相当于在“不改变数据几何密度”的方向上做响应式：柱子不会随着屏幕无约束变粗/变细，用户看到的“数据视觉重量”保持一致，从而支撑体验连续。

## 柱状图响应式设计
名词定义及计算关系
X轴区域宽度 = 设备/卡片宽度 - 左右边距 - Y轴标签区域宽度
柱子总宽度 = X轴区域宽度 × 数据墨水比
理论单个柱子宽度 = 柱子总宽度 / 数据组数
实际柱子宽度 = 理论单个柱子宽度 最大柱宽限制32vp，最小柱宽限制4vp

单柱状图、堆叠柱状图
屏幕尺寸变化时，图表信息量应保持恒定，数据墨水比应保持恒定。参考黄金比例，柱宽：平均柱区域 = 0.618 : 1.618 ≈ 40%
为保证组数过少时/屏幕尺寸过大时，柱子由于比例拉伸显得过于粗大，最大柱宽限制为32vp；为保证可识别性，最小柱宽限制为4vp。
多组柱状图
参考黄金比例，柱宽之和：平均柱区域 = 0.618 : 1 ≈ 60%。组内间距 = 柱宽 * 0.25
为保证组数过少时/屏幕尺寸过大时，柱子由于比例拉伸显得过于粗大，最大柱宽限制为32vp；为保证可识别性，最小柱宽限制为4vp。为保证分组视觉上成组，最大组内间距限制为8vp；为保证可辨别性，最小组内间距限制为2vp。

## 多组数据小屏展示策略：横向滑动/翻页
当屏幕尺寸较小且存在多组数据时，单屏柱宽可能过窄，导致可读性下降。此时可通过“左右滑动展示”提升单屏柱子的可读性，并根据业务目标选择不同策略。

### 策略A：连续滑动展示（横向滚动）
核心目标：以手势连续探索为主，保证用户观察过程尽量连贯。
体验优势：
- 柱子的顺序/邻近关系更自然，便于用户追踪趋势或形态变化
- 用户可以随时来回调整观察区间，降低寻找信息的成本
适用场景：
- X轴或维度本身具有明确的连续意义（时间、连续区间、可自然排序的维度）
- 用户主要关注“趋势/变化”，而不是“必须完整看完一整批才切换”
实现建议（影响体验的关键点）：
- 为了让柱宽稳定可读，可采用“视口展示固定数量柱子 + 吸附 snap 到格子/粒度”的折中方案
- 在 UI 层提供进度提示（如页点/滑动进度条/当前区间索引），避免用户迷失在滚动位置

### 策略B：左滑进行翻页展示（分页切换）
核心目标：每一屏呈现一组相对完整、语义上独立的数据集合。
体验优势：
- 每次切换的“内容边界”清晰，用户知道当前查看的是哪一批
- 认知负担更低，适合离散对比或按组查看
适用场景：
- 数据天然是离散分组且业务希望“按组/按批查看”（设备组、业务模块、实验批次等）
- 用户更关心“这一批是否看清”，而不是连续追踪中间过渡
实现建议：
- 提供明确的页码/当前批次信息，必要时配合左右按钮与手势
- 每页固定展示数量，避免翻页时柱宽/间距大幅波动

### 推荐选择逻辑（按业务目标选）
- 若用户主要进行“趋势探索/相邻对比”，优先选择“连续滑动展示”（最好带 snap 保证柱宽稳定）
- 若用户主要进行“按批次查看/离散对比”，优先选择“左滑翻页展示”
- 若无法确定业务偏好，默认采用“连续滑动 + 固定粒度吸附”的折中，兼顾探索体验与可读性稳定
